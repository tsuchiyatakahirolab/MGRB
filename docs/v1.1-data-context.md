# MGRB v1.1 data, context, and research workflow

This document describes the unreleased v1.1 development scope. MGRB v1.0.0 and its tag remain
immutable.

## Data and layer registry

`config/data_layers.yml` is the machine-readable MGRB Data & Layer Registry. Run `mgrb layers`
to inspect the same catalog grouped for the UI. Every record states provider, dataset, URL,
semantic class, coverage, resolution, format, acquisition method, license, attribution,
redistribution and commercial-use status, version/date, source class and connector status.

Source classes are:

- `OPEN`: an implemented connector or import path with stated public terms;
- `REFERENCE_ONLY`: visible in the registry but never enabled, scraped or packaged;
- `BYO_LICENSED`: a local importer whose redistribution remains disabled until the user reviews
  the applicable terms.

TeleGeography is `REFERENCE_ONLY`. MGRB does not scrape or redistribute its cable routes and does
not fabricate missing routes. OpenStreetMap cable extracts are import-only under ODbL 1.0. The
NGA World Port Index connector uses the official provider CSV and records its retrieval checksum.

## Multiple datasets and time filtering

The UI accepts multiple inputs and asks for a semantic kind per file: track, official
observation, event, port, cable landing point, submarine cable, or other infrastructure. Every
input receives its own stable `dataset_id`, QC record, source hash and GeoPackage layer.
Segmentation is grouped by both dataset and entity, so separate files are never joined merely
because they name the same vessel.

Start and end dates apply to positions, official observations, events and derived tracks. The
period is recorded in the build, dataset, product and QGIS specifications. For CLI use, repeat
`--input-kind` in the same order as `--input`:

```bash
mgrb build taiwan-east \
  --from 2026-01-01 --to 2026-01-31 \
  --input research-track.csv --input-kind TRACK \
  --input official-observations.csv --input-kind OFFICIAL_OBSERVATION \
  --input context-events.geojson --input-kind EVENT \
  --context-layers nga_world_port_index \
  --output-name taiwan-multi-source-study
```

## Evidence-safe semantics

Official observations preserve exact, approximate and map-derived methods, uncertainty, source
URL and timestamp. Event geometry remains `EVENT_GEOMETRY`; infrastructure remains context.
Neither is promoted to `RAW_POSITION_TRACK`. Sparse official points may only form explicitly
labelled inferred connections under the existing evidence rules.

## Transparent analytics

Each build writes `metadata/analytics-manifest.json`, `derived/track_coverage.csv`, and the
applicable CSV/GeoPackage derivatives for:

- observation count, temporal span, density, gaps, maximum gap and segment count;
- requested-period fraction observed;
- EEZ/reference-zone crossing candidates;
- distance to a selected EEZ reference boundary and port;
- repeated-area visits;
- low-speed candidates.

These are descriptive geometric or threshold metrics. They do not infer espionage,
surveillance, militia status, hostile intent, or deliberate AIS disablement. Maritime-zone
crossings are candidates against sourced reference geometry, not legal determinations.

## Public/private firewall

`mgrb.firewall` audits tracked public files and every portable package before ZIP creation. It
blocks `.local`, browser profiles, collector SQLite, owner GFW raw/derived files, session data,
tokens, private keys, and private/paid AIS or SAR filename classes. This is a permanent release
gate. The private collector and all private acquisition state remain outside the public source
tree and public artifacts.
